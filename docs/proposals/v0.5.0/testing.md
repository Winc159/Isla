# v0.5.0 测试与验收计划

## 1. 完成定义

v0.5.0 只有一条权威用户验收路径：

> 用户在 Resource 输入框粘贴分享信息，选择允许的输出位置；系统完成解析、并发排队、下载、识别、必要的密码尝试、完整解压与原子发布，最终返回可用的完整内容目录。

该路径必须在 Windows 上可验证，并在 N100 Linux 上完成最终部署验收。Web UI 不是唯一验收入口；同一流程必须可由 API 自动编排。

个人网盘补充验收：`GET /baidu/tree` 能从 `/` 进入 `/apps/bdpan`，WebUI 支持上一级、目录展开、文件元数据和多选；`baidu-path` 下载不携带分享/转存参数，完成后不残留人工决策。终态任务可重新下载或清除记录，本地目录浏览只返回受管根内相对路径并拒绝越界。

## 2. 测试层级

### 2.1 单元测试

- 配置与 Profile：primary/worker 角色、缺失 Worker、非法并发、managed root ID、秘密脱敏；
- 结构化推理：schema 校验、超时、取消、非法 JSON、超预算和 Provider 错误；
- 输入解析：链接、提取码、密码候选、重复候选、歧义与人工确认；
- 状态机：合法迁移、非法迁移、终态不可逆、revision 冲突和重试预算；
- 调度：池隔离、公平性、lease、heartbeat、陈旧租约回收和 quiescence；
- 文件识别：magic bytes、SFX/尾部签名、分卷命名、伪扩展名和误命中；
- 发布：命名冲突、跨盘复制校验、manifest 和幂等 finalize。

### 2.2 API 契约测试

- 所有 `api.md` endpoint 的成功、错误和版本兼容；
- Job 创建幂等键；
- revision 乐观并发控制；
- SSE 游标重连、事件顺序和终态唯一；
- 浏览器不能提交任意绝对路径，只能提交已配置 root ID；
- token、Origin、body size、速率与日志脱敏边界；
- Isla Host 不可用时 Resource Job 进入可解释的等待/失败状态，不拖垮 Resource API。

### 2.3 状态与恢复测试

- 每个 stage 崩溃前、外部动作中、外部动作完成后但落库前的恢复；
- Resource Service 重启后回收 running lease；
- Isla Host 单独重启不影响正在进行的下载或解压；
- Resource Service 崩溃不影响 Isla 主对话；
- 取消下载、识别、解压和发布时只有一个 Job 终态；
- 已完成 Artifact 不因重试被重复发布；
- 人工补充密码或分卷后从最窄安全阶段继续。

## 3. 并发验收

以下均为 P0：

1. `downloadConcurrency = 2` 时，两个真实或受控 runner 下载存在可证明的时间重叠；
2. 第三个下载等待槽位，前两个任一完成后继续；
3. 下载池占满时，已有文件的 inspect/extract 不被同一 semaphore 阻塞；
4. 一个大 Job 不能永久饿死后来的小 Job；
5. 取消一个 Job 不取消其他 Job；
6. 重启后不会把陈旧 lease 计入并发槽位；
7. 并发配置超出安全上限时启动失败，而非静默接受。

## 4. Managed Roots 验收

- 新文件写入后自动发现；
- 文件仍增长时不入队，稳定窗口后才处理；
- 原子 rename、分段写入、临时扩展名改名均能通过周期扫描收敛；
- 文件系统事件丢失后，reconciliation 仍能发现文件；
- 重启、重复扫描、mtime 变化和内容变化的 ledger 语义明确；
- 输出目录可选但必须位于允许 root；
- 输入目录与输出目录重叠时不会递归重复消费自己的产物；
- Windows 路径大小写、盘符与 Linux 大小写语义分别测试。

## 5. 压缩样本矩阵

所有 P0 样本必须使用可公开或本地生成的无敏感测试数据：

| 场景 | 预期 |
| --- | --- |
| 普通 ZIP/7z/RAR | 完整解压并发布 |
| 正确单密码 | 自动命中并发布 |
| 多个密码候选，前几个错误 | 按顺序尝试并记录安全摘要 |
| 密码全部错误 | 进入 `needs_input`，可补充后继续 |
| 压缩包改成无关扩展名 | 依内容识别 |
| MP4 尾部追加 RAR | 保留载体证据并提取内嵌归档 |
| RAR5 | 使用支持的 runner 完整解压 |
| RAR/7z 多分卷 | 聚合完整分卷后解压一次 |
| 缺少中间分卷 | 不发布部分结果，报告缺卷 |
| 损坏归档 | 明确失败，不污染输出 |
| 普通 MP4 含偶然字节序列 | 不误判为可解压归档 |

## 6. 解压安全矩阵

- `../`、绝对路径、Windows drive/UNC 路径穿越；
- 指向 managed root 外部的 symlink/hardlink；
- 超文件数、超总大小、超单文件大小和异常膨胀率；
- 文件名编码异常、保留名、大小写冲突和过长路径；
- 解压工具超时、被取消、异常退出或输出不完整；
- staging 中出现未知外部修改；
- 跨文件系统发布中断后的临时目录恢复；
- 永不删除用户原始输入，除非未来有独立且明确授权的保留策略。

## 7. Worker 模型测试

### 7.1 离线

- Fake Provider 覆盖结构化成功、格式修复上限、拒绝、超时和取消；
- Worker 不得到 Tool schema、Session 历史、Memory 或主对话 system prompt；
- Worker Profile 修改在规定的重启/刷新边界生效；
- primary 与 worker 使用不同模型时，主会话请求不串到 worker。

### 7.2 真实评估

- 使用用户授权的百炼 `qwen-plus-2025-07-28` 作为 Worker；
- 以脱敏分享文本覆盖正常、混杂说明、多个密码和歧义案例；
- 保存 schema 合格率、人工修订率、延迟和失败原因；
- 真实正文与 Provider 原始响应只进入 `.isla-local/evaluations/v0.5.0/`，不得进入仓库。

## 8. 百度下载验收

- 正确分享链接与提取码可枚举并下载；
- 两个任务真实并发；
- 错误提取码、失效分享、登录过期、限流、断网和磁盘不足均有稳定结果；
- 下载取消后外部进程收敛，不继续写文件；

### Windows 真实闭环记录（2026-10-15）

- `bdpan 3.8.7` 登录有效，会员开通后 159 字节改后缀 ZIP 上传成功；
- 生成 7 天分享链接与提取码成功；
- 同一账号尝试转存自己的分享被百度拒绝，返回 `errno=13045 prohibit transfer self share link`，这是平台限制，不应自动重试；
- 兜底路径使用 `cp` 复制到另一个 `/apps/bdpan/` 子目录后直接下载成功；
- Windows 下载目标若只传已存在目录，CLI 会把目录当作目标文件并在 rename 阶段失败；适配器必须传入明确的本地文件路径；
- 下载文件与上传前文件 SHA256 一致；`.pkg` 文件被 7-Zip 按 ZIP 内容识别，测试与解压成功，内部文本内容一致；
- 真实账号标识、原始任务日志和下载产物只保存在 Git 忽略的本地目录，不进入仓库。
- 重试不会重复发布；
- runner 的凭据、Cookie 和 token 不进入数据库普通字段、SSE、Web 页面、测试快照或日志；
- Windows 与 N100 Linux 使用同一上层 Job/API/状态机契约，平台差异限制在 runner 与路径适配层。

### Resource Web 闭环复验（2026-10-15）

- 在隔离受管目录中放入后缀改成 `.mp4` 的真实 ZIP，手工扫描自动创建 Job、真实调用 7-Zip 并完成发布；
- `真实整理样本/电影名称/未命名文件夹/{movie.mp4,cover.jpg}` 被保守整理为 `真实整理样本/电影名称/{movie.mp4,cover.jpg}`，空目录删除，有意义目录保留；
- 同一文件再次扫描创建 0 个新 Job；修复了手工扫描与 1 秒周期扫描之间可能重复排队的账本竞态，并加入 queued 状态回归测试；
- 服务停止后加入第二个改后缀归档，重启后持久 watch 自动发现；最终 2 个 Job completed、0 个 failed、2 个输出目录；
- 两个约 1.3 KiB 文件上传并分别生成 7 天分享，批量文本成功拆成两个并发下载 Job；百度对同账号自分享返回业务 JSON `code=1`/`errno=13045`，但 CLI 进程退出码为 0；
- Runner 已改为优先使用 JSON 业务码并映射 `BDPAN_SELF_SHARE_FORBIDDEN`，避免误判成功后进入解压；远端测试文件随后已删除；
- 由于百度禁止同账号处理自分享，本轮无法证明两个外部分享成功下载；仍需另一个账号或外部小文件分享完成成功路径门禁。

## 10. 跨平台真实验收

### 10.1 Windows 开发验收

必须通过：

1. 启动 Isla Host 与 Resource Service 两个进程；
2. 配置 Worker 和至少一个 managed root；
3. 同时提交至少两个百度下载任务；
4. 覆盖全部压缩复杂场景的本地样本；
5. 验证重启恢复、取消、补充密码和选择输出位置；
6. 完成全量离线测试、typecheck、build 和 package 检查。

### 10.2 N100 Linux 最终验收

必须通过：

1. 原生 Node.js 部署并以服务方式分别启动两个进程；
2. 机器重启后两个服务和 SQLite 状态恢复；
3. 浏览器经私有局域网访问，并满足 token/Origin 边界；
4. 至少两个真实下载并发；
5. 至少一个真实分享从粘贴输入完成到完整解压目录；
6. managed root 自动发现一个新文件并完成整理；
7. 验证磁盘空间、权限、7zz/unrar 可用性和失败诊断；
8. 运行 24 小时观察无遗留活跃 lease、僵尸进程或重复消费。

## 11. 发布阻断条件

任一项成立都不得标记 v0.5.0 完成：

- 只能串行下载；
- 只能通过 UI、不能通过 API 自动验收；
- 任一承诺的复杂压缩场景没有 P0 样本；
- 错误密码、缺卷或损坏归档仍会发布部分目录；
- Worker 泄漏主会话、Tool、Memory 或秘密；
- 用户可通过 API 指定 managed roots 之外的任意输出路径；
- 任一进程重启会让 Job 永久卡在 running；
- Windows 不可运行，或 N100 Linux 最终路径未通过；
- 真实评估资料、凭据、Cookie、token 或私人分享内容进入 Git 范围。

## 12. 验收证据

仓库内只保存脱敏汇总：版本、平台、配置摘要、用例结果、耗时、错误码和已知限制。原始真实输入、Provider 响应、下载清单与敏感日志保存在 Git 忽略的 `.isla-local/evaluations/v0.5.0/`。

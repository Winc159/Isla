# Resource React UI 设计

本文定义 Resource Web 工具台从内嵌 HTML/JavaScript 迁移到 React 时的界面和前端边界。迁移只改变展示与浏览器状态管理，不改变 Resource Job、Scheduler、数据库、文件处理或 HTTP API 语义。

## 目标

- 保留当前桌面版的信息结构和双栏布局，降低重新学习成本。
- 解决长标题、文件路径、错误信息和事件数据撑破模块的问题。
- 让设置、任务创建和任务队列使用统一的网格、间距和操作区。
- 使用 React 管理轮询、展开、表单和 mutation 状态，避免服务端刷新重置局部交互。
- 为后续拆分任务详情、筛选和实时事件保留清晰边界，但不在本次迁移中提前实现。

## 不改变的内容

- “资源目录”和“Resource Worker”继续常驻展开，不折叠到抽屉或设置页。
- 百度下载、目录整理、任务确认、重试、取消、重复、删除、日志和资源树的现有能力保持完整。
- 页面继续由只监听 loopback 的 Resource Service 提供。
- 浏览器只通过 `/api/v1/resource` 操作，不直接访问 SQLite、配置文件或 staging。
- API Key、分享码和解压密码不进入 URL、日志、Query Cache 持久化或浏览器存储。

## 页面结构

桌面端继续使用当前从上到下、再进入双栏工作区的结构：

```text
┌──────────────────────────────────────────────────────────────┐
│ Isla Resource                         服务状态 / 刷新时间    │
│ 资源处理工作台                                             │
├───────────────────────────┬──────────────────────────────────┤
│ 下载通道                  │ 解压与整理通道                  │
├───────────────────────────┴──────────────────────────────────┤
│ 资源目录设置（常驻展开）                                   │
├──────────────────────────────────────────────────────────────┤
│ Resource Worker（常驻展开）                                │
├──────────────────────┬───────────────────────────────────────┤
│ 百度下载 / 目录整理  │ 任务队列                              │
│ 创建任务             │ 状态、阶段、进度、操作                │
│                      │ 按需展开事件日志和资源树               │
└──────────────────────┴───────────────────────────────────────┘
```

## 文件工作台与密码本（设计基线）

Resource 后续增加第三个工作区“文件工作台”，用于在受管目录内浏览和控制下载、解压产物；密码本作为文件工作台的辅助模块展示。两者都通过 Resource API 操作，前端不得直接访问文件系统或 SQLite。

### 文件工作台范围

- 只读浏览：目录树、文件列表、面包屑、名称/大小/修改时间/类型和刷新。
- 文件操作：重命名、移动、删除、还原。
- 解压入口：选择压缩包、选择输出目录、调用现有 `ArchiveOrganizer` 创建 Resource 任务。
- 所有接口只接收 `managedRootId + relativePath`，服务端统一校验路径，禁止绝对路径、`..` 越界和符号链接逃逸。

### Isla 回收站

文件删除不直接调用 `rm`，而是移动到受管目录下的 Isla 回收站，并记录原始路径、回收时间、大小和操作 ID。回收站策略同时受时间和容量约束：

- 默认保留期限：30 天；过期项目自动清理。
- 默认容量上限：100 GiB。
- 写入新项目后，如果总大小超过上限，按回收时间从旧到新删除，直到回到上限以内。
- 清理只删除回收站内容，不影响正常受管目录；正在执行任务引用的文件不得被回收。
- 还原前检查原路径是否冲突，要求用户选择覆盖、自动改名、其他目录或取消。

保留期限和容量属于 Resource 设置，可在后续设置面板调整；第一版使用上述安全默认值。清理和还原都写入 Resource 事件日志。

### 密码本

现有 `resource_archive_passwords` 表扩展为可管理的密码本。局域网模式下密码明文展示，不做遮罩；但仍不得进入 URL、普通日志、Query Cache 持久化或测试快照。

密码本支持：

- 查看密码、成功次数和最近成功时间。
- 新增单个密码或多行批量导入。
- 去重、空行过滤和长度/数量限制。
- 删除单个或多个密码。
- 解压任务按成功次数和最近成功时间优先尝试密码本，并继续支持当前任务临时密码。

建议 API：`GET/POST /settings/passwords`、`DELETE /settings/passwords/:id`。密码本删除只影响后续自动尝试，不修改已经完成的任务记录。

### 任务与解压边界

“继续解压”必须复用 `ArchiveOrganizer` 和现有 `ResourceScheduler`，不在文件工作台实现第二套解压脚本。这样可以继续复用密码请求、进度、事件、失败、重试和资源树能力。

### 分阶段交付

1. 只读文件浏览、压缩包识别和密码本查看/新增/删除。
2. 重命名、移动和 Isla 回收站删除/还原。
3. 文件工作台发起继续解压任务，接入密码本和现有任务卡。
4. 回收站策略设置、批量操作、冲突解决和完整自动化测试。

页面最大宽度为 `1440px`。工作区左栏使用 `minmax(360px, 420px)`，右栏使用 `minmax(0, 1fr)`，栏间距为 `20px`。设置区与工作区共用页面内容边界。

在 `900px` 以下，通道、设置网格和工作区变为单列；在 `520px` 以下减小页面与卡片内边距，但不隐藏功能。

## 视觉系统

Resource 是个人资源处理控制台，不采用通用 SaaS 仪表盘的高饱和渐变和装饰性统计卡。唯一的识别元素是任务的“处理轨道”，用于表达下载、检查、解压、验证和发布的真实阶段。

### 颜色

| Token | 值 | 用途 |
|---|---|---|
| `--color-canvas` | `#F3F5F7` | 页面背景 |
| `--color-surface` | `#FFFFFF` | 卡片与输入区 |
| `--color-ink` | `#172333` | 主文本 |
| `--color-muted` | `#667487` | 次要信息 |
| `--color-line` | `#D8E0E8` | 边框和分隔 |
| `--color-process` | `#2764D7` | 运行状态和主操作 |
| `--color-attention` | `#C87616` | 等待用户处理 |
| `--color-success` | `#17785B` | 完成 |
| `--color-danger` | `#B63C3C` | 失败和破坏性操作 |

颜色必须与文字、图标或形状共同表达状态，不能作为唯一提示。

### 字体

- 页面标题：`"Segoe UI Variable Display", "PingFang SC", sans-serif`。
- 正文和表单：`"Segoe UI Variable Text", "PingFang SC", system-ui, sans-serif`。
- 路径、时间、事件名和技术字段：`"Cascadia Code", ui-monospace, monospace`。

不加载远程字体，避免本地工具台因网络或隐私设置产生额外依赖。

### 尺寸与节奏

| 项目 | 规格 |

| 页面水平内边距 | 桌面 `30px`，中屏 `20px`，小屏 `12px` |
| 区块间距 | `20px` |
| 卡片内边距 | `20px` |
| 卡片圆角 | `16px` |
| 控件高度 | 输入 `42px`，普通按钮 `38px`，主按钮 `42px` |
| 表单字段间距 | `16px` |

| 标题与说明间距 | `4px` |

## 文本约束

文本处理由内容类型决定，不能统一使用 `overflow: hidden`：

| 内容 | 默认展示 | 完整内容入口 |
|---|---|---|
| 任务标题 | 单行省略 | 原生 title 或展开详情 |
| 文件路径 | 中间省略，保留根和文件名 | 可选择文本的完整路径行 |
| 状态和阶段 | 固定列宽，不换行 | 不需要 |
| 错误说明 | 最多两行 | “展开错误详情” |
| 用户决策说明 | 正常换行，不截断 | 当前卡片内完整显示 |
| 事件类型 | 固定宽度、单行 | 不需要 |
| 事件数据 | 可换行的等宽文本 | 详情行完整显示 |
| 设置说明 | 最大宽度 `72ch` | 默认完整显示 |
| 按钮文案 | 单行，按钮高度固定 | 操作过多时进入“更多操作” |

任意用户或文件系统文本都必须允许断行且不能扩大页面宽度。任务标题和路径容器必须设置 `min-width: 0`。

## 模块规范

### 设置卡片

资源目录和 Worker 使用相同的卡片结构：标题区、说明区、字段区和操作区。操作区固定在字段区下方，不因说明文字长度上下漂移。

资源目录每行在宽屏使用：

```text
名称 | 路径 | 扫描 | 可输出 | 删除
```

路径列占据剩余空间；复选项列宽固定；删除操作不与保存主操作争夺视觉优先级。

Worker 在宽屏使用四列字段网格。API Key 独占下一行，保存、测试和状态位于统一操作行。保存后重启的提示作为状态文字，不使用永久 Toast 代替。

### 创建任务

保留“百度下载”和“文件解压 / 整理”两个页签。切换页签时保留各自尚未提交的输入。目录浏览结果属于对应表单，不影响任务列表刷新。

主操作按钮占满表单内容宽度；目录浏览、上一级和批量选择属于次级操作，视觉权重低于创建任务。

### 任务卡

任务卡由四个稳定区域组成：

```text
标题行：任务标题                         状态
元信息：来源 · 当前阶段 · 更新时间
阶段轨道：当前处理阶段和进度
内容区：失败、等待确认、日志或资源树
操作区：详情操作                    主要操作 / 更多
```

只有存在失败、用户决策或展开内容时才渲染内容区。卡片刷新不能关闭已展开的日志和资源树，也不能清空用户正在填写的密码或修正文本。

任务操作按优先级排列：

1. 当前唯一可继续任务的主操作；
2. 查看日志、查看资源树；
3. 重试、重新整理、重复；
4. 取消和删除。

删除始终需要明确确认。执行 mutation 时，只禁用与当前任务冲突的操作，不阻塞整个页面。

### 事件日志和资源树

日志按时间、事件名和数据三列展示；窄屏改为上下布局。未知事件类型仍需可显示，不能因为前端枚举缺失而丢弃。

资源树以层级和连接线表达父子关系。长路径不决定缩进宽度；每层缩进固定，名称列可截断，大小和状态列保持对齐。

## React 状态边界

- TanStack Query 管理任务、事件、资源树、Resource 设置和 Worker 状态。
- `useState` 管理页签、展开任务、Toast 和当前目录浏览位置。
- 表单使用局部受控状态；目录多行编辑可使用 `useReducer`。
- 第一版不引入 Redux 或 Zustand。
- 两秒轮询只更新任务 Query；页面失焦时降低或暂停轮询，重新聚焦后立即刷新。
- mutation 成功后按资源精确失效 Query，不执行全页面重载。
- 不启用 Query Cache 持久化。

## 迁移步骤

1. 建立 React、Vite、TypeScript 和前端测试骨架，生成可由 Resource Service 托管的静态资源。
2. 建立 API Client、Query Client、错误映射和测试 fixture。
3. 按当前布局实现只读页面壳、通道摘要、任务队列、阶段轨道、日志和资源树。
4. 迁移任务确认、取消、重试、重新整理、重复和删除。
5. 迁移百度下载、本地目录整理和目录浏览表单。
6. 迁移资源目录与 Worker 设置，并保持常驻展开。
7. 完成响应式、键盘操作、文本溢出、敏感字段和视觉回归验证。
8. 功能对齐后将 `/resource` 切换到 React 产物，并删除旧内嵌页面。

迁移期间旧页面保持正式入口，新页面使用临时开发入口验证。切换后不长期维护两套 UI。

## 验收条件

- 现有 Resource UI 能力全部可从 React 页面完成。
- 任务轮询不重置表单、页签、展开区域和临时输入。
- 320px 至 1440px 宽度无水平页面溢出。
- 超长标题、路径、错误和事件数据不破坏卡片与网格对齐。
- 键盘可以到达所有表单和任务操作，焦点样式可见。
- `prefers-reduced-motion` 下关闭非必要过渡。
- API Key、分享码和解压密码不进入浏览器持久化、URL、普通日志或测试快照。
- 默认测试无网络、无真实凭据；前端构建纳入 `npm run build` 和发布包检查。
